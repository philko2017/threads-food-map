# 階段 1「收單流程」說明

## 檔案清單
- `收單流程.json`：n8n 工作流程匯入檔（名稱：`脆友美食地圖｜收單（自動執行）`）。
- `測試資料.sh`：五筆情境測試腳本（需設定環境變數 `WEBHOOK_URL`）。
- `說明.md`：本說明文件。

---

## 節點說明

1. **收單 Webhook**（`POST /webhook/food-map-submit`）
   - `responseMode: responseNode`，允許跨網域（`allowedOrigins: "*"`）。
2. **檢查資料**（Code）
   - 驗證必填欄位：`店名`、`類別`（限 8 種）、`有沒有實體店面`、`縣市`、`區`、`同意聲明 === true`。
   - 有實體店面時 `地址` 必填；`Threads 帳號` 與 `IG 帳號` 至少填一個（自動去掉開頭 `@`）；`一句話介紹` 上限 30 字。
   - 依欄位上限裁切並去除前後空白；不合格回傳 `400 { ok: false, error, message }`。
3. **資料是否合格**（Switch）
   - 不合格導向 **回應格式錯誤**；合格導向 **讀取店家試算表**。
4. **讀取店家試算表**（Google Sheets）
   - 讀取「店家」工作表全部列（已開啟 `alwaysOutputData: true`，試算表無資料列時仍會繼續）。
5. **查重複**（Code）
   - 將 `店名`、`縣市`、`區` 轉半形、去空白、轉小寫後比對；若已有相同店名＋同縣市＋同區且 `狀態 !== "已下架"`，回傳 `409 { ok: false, error: "duplicate", message: "這家店已經在地圖上了" }`。
6. **是否重複或需轉座標**（Switch）
   - 重複 → **回應重複**（409）。
   - 有實體店面且有地址 → **地址轉座標**（OpenStreetMap Nominatim 免費轉座標，免金鑰，失敗不中斷）。
   - 只做宅配（無地址）→ 直接進 **組一列**。
7. **組一列**（Code）
   - 產生唯一編號 `FM-XXXXXX`、台灣時間 ISO 字串、預設狀態 `確認中`。
   - 有跑 Geocoding 且成功時填入 `緯度`、`經度`（`geocoded: true`），查不到則留空（`geocoded: false`）。
8. **寫入試算表**（Google Sheets）
   - 將 20 個欄位依序新增一列到「店家」工作表。
9. **回應成功**（Respond to Webhook）
   - 立即回傳 `200 { ok: true, id, status: "確認中", geocoded, message: "已上架，確認中，三天內完成審核" }`，不讓表單頁等 LINE API。
10. **通知 Phil**（HTTP Request）
    - 呼叫 LINE Messaging API Push 通知新店家資訊與 Threads/IG 連結（失敗不影響主流程）。

---

## 匯入前要建的憑證與佔位字替換

### 1. 在 n8n 建立（或確認）兩個憑證
1. **Google Sheets OAuth2 API**：名稱 `Google philko.2017`（供讀取／寫入試算表使用）。
2. **Header Auth**：名稱 `脆友美食地圖 LINE`，Header Name 填 `Authorization`，Value 填 `Bearer <LINE Channel Access Token>`。

> 地圖與地址轉座標已改用免費開源的 Leaflet + OpenStreetMap Nominatim，**不需要** Google Cloud 帳單或 Geocoding API 金鑰。

### 2. 匯入後在節點中填入實際值（取代佔位字）
* `__SHEET_ID__`：在「讀取店家試算表」與「寫入試算表」兩個節點填入你的 Google 試算表 ID。
* `__NOTIFY_TO__`：在「通知 Phil」節點的 JSON Body 中，把 `__NOTIFY_TO__` 換成你的 LINE User ID。
* 兩個憑證欄位：匯入 JSON 後請在 n8n UI 重新選取上面對應的「Google 試算表」與「LINE」憑證。

## 測試步驟

1. 確認 Google 試算表「店家」工作表第一列已放好這 20 個表頭（順序固定）：
   `編號`、`送出時間`、`店名`、`類別`、`有沒有實體店面`、`縣市`、`區`、`地址`、`Threads 帳號`、`IG 帳號`、`一句話介紹`、`電話`、`營業時間`、`同意聲明`、`緯度`、`經度`、`狀態`、`審核備註`、`審核日期`、`店家 LINE 帳號`
2. 匯入 `收單流程.json`，綁定憑證並填入 `__SHEET_ID__` 與 `__NOTIFY_TO__`，啟用（Active）工作流程。
3. 在終端機執行五筆測試：
   ```bash
   chmod +x 測試資料.sh
   export WEBHOOK_URL="https://你的n8n網域/webhook/food-map-submit"
   ./測試資料.sh
   ```
4. 驗收結果：
   - (a) 回 `200`，`geocoded: true`，試算表多一列且有經緯度，LINE 收到通知。
   - (b) 回 `200`，`geocoded: false`，試算表多一列且經緯度留空，LINE 收到通知。
   - (c) 回 `200`，`geocoded: false`，試算表多一列且經緯度留空，LINE 收到通知。
   - (d) 回 `409`，`error: "duplicate"`，不寫入試算表。
   - (e) 回 `400`，`error: "store_name"`，不寫入試算表。
   - 測試完成後，記得把試算表中的測試資料列刪除。
